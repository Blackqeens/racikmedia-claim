Uji POST melewati endpoint Supabase, tetapi fungsi melaporkan HTTP 404 dari Gemini untuk model default gemini-2.5-flash. CORS dan deployment bukan lagi hambatan utama. Checklist di bawah membantu memastikan model, API key, payload, dan hasil langsung dari akun pemilik.

3. Pastikan model dan akses Gemini

  1. Buka Google AI Studio/API Keys dan pastikan key terikat ke proyek Google Cloud yang benar.
  2. Di Google Cloud Console, pastikan Generative Language API aktif pada proyek terkait.
  3. Pastikan pembatasan API key mengizinkan Generative Language API. Jangan menghapus pembatasan keamanan secara permanen hanya untuk mengatasi uji gagal.
  4. Periksa model yang tersedia/diizinkan untuk key tersebut di dokumentasi atau daftar model resmi. Cocokkan nama model persis dengan GEMINI_TRANSLATION_MODEL atau default source.
  5. Periksa status billing, kuota, rate limit, pembatasan wilayah, dan status layanan Google. HTTP 404 perlu dicocokkan dengan pesan provider; bisa berarti model/path tidak tersedia untuk konfigurasi itu.
  6. Gunakan metode API dan model yang sama saat menguji manual. Jangan menyimpulkan hanya dari nama model yang terlihat di contoh lama.

Catatan keamanan: fungsi saat ini mengirim key ke Google melalui query parameter ?key=... dari secret server, bukan dari browser. Query string dapat tercatat di sistem observabilitas/proxy; batasi akses log dan jangan pernah mencetak URL lengkap yang berisi key.

4. Tes jalur HTTP/CORS dan POST

A. Preflight CORS

Dari terminal, jalankan permintaan OPTIONS berikut. Respons yang diharapkan adalah HTTP 200 dan Access-Control-Allow-Origin yang tepat:

curl.exe -i -X OPTIONS "https://bwyzqqetpgcqjnnwrzhh.supabase.co/functions/v1/translate-page" `
  -H "Origin: https://dapper-bienenstitch-b63263.netlify.app" `
  -H "Access-Control-Request-Method: POST" `
  -H "Access-Control-Request-Headers: content-type,authorization,apikey"

B. Uji POST lewat halaman situs

  1. Buka situs Netlify secara normal, login bila deployment meminta autentikasi, lalu buka Developer Tools → Network.
  2. Pilih English. Cari request /functions/v1/translate-page; pastikan method POST dan payload berisi {"lang":"en","texts":[...]}.
  3. Pastikan request hanya mengirim teks halaman di body; frontend tidak mengirim URL halaman untuk di-fetch oleh fungsi.
  4. Periksa response. Target sukses: HTTP 200, JSON {"translations":["..."]}, jumlah hasil sama dengan jumlah teks yang dikirim, dan hasil terjemahan tidak kosong.
  5. Uji satu teks sederhana lebih dulu, kemudian ganti bahasa/halaman untuk melihat apakah teks terjemahan diterapkan dan tersimpan di cache.

6. Catatan hasil pemeriksaan otomatis terakhir

  • Fungsi Supabase translate-page: ACTIVE, versi 3 pada proyek yang diperiksa.
  • Preflight CORS untuk origin Netlify: HTTP 200 dengan origin yang sesuai.
  • POST dari halaman lokal ke fungsi: HTTP 502, provider Gemini HTTP 404 untuk model default gemini-2.5-flash.
  • Secret GEMINI_API_KEY dan APP_ALLOWED_ORIGINS ditemukan di proyek saat listing secret; nilainya tidak dibaca untuk laporan ini.
  • Situs Netlify merespons 401 pada pemeriksaan HTTP tanpa sesi. Verifikasi konten UI melalui browser dengan akses normal.
