Versi ini mencakup: Base Layout, Language Switcher Global, FORL Prevention, dan Struktur Direktori Final.

1. Latar Belakang & Solusi

Platform BOB memiliki 3 pilar halaman — Artikel/Jurnal, Marketplace, dan Penyedia Jasa/Showstore — dengan ancaman bug desain yang sama:

  • Mengulang kode Navbar & Footer di setiap halaman → satu perubahan harus diedit puluhan file
  • Language Switcher tidak sinkron antar halaman karena disimpan terpisah-pisah
  • Layar goyang horizontal (horizontal overflow) di smartphone karena elemen melebihi viewport
  • Bahasa "berkedip" dari default ke pilihan user saat halaman dimuat (Flash of Wrong Language)

Solusi: Arsitektur terpusat berbasis fetch-include — Navbar dan Footer disimpan sebagai satu file snippet yang di-fetch oleh semua halaman. Perubahan pada satu file → semua halaman otomatis terupdate.

Prinsip Kunci: "Tulis sekali, pakai di mana saja." Tidak ada framework, tidak ada build tool — murni HTML + Tailwind CDN + Vanilla JS yang bekerja langsung di browser.

3. Cara Membuat Halaman Baru (3 Langkah)

1
Salin layouts/base.html
Salin file ini ke lokasi halaman baru. Contoh: pages/main/checkout.html
2
Sesuaikan path fetch()
Ubah path relatif di tag <script> fetch navbar dan footer sesuai kedalaman folder halaman baru. Lihat tabel di bawah.
3
Isi konten di dalam <main id="page-content">
Tulis HTML konten spesifik halaman. Tambahkan atribut data-id / data-en untuk teks yang perlu diterjemahkan. Selesai.

4. Sistem Language Switcher — Cara Pakai

Sistem terjemahan bekerja sepenuhnya dengan atribut HTML data-*. Tidak perlu menyentuh file JS.

Atribut yang Didukung

AtributFungsiContoh
data-id / data-en Ganti teks node elemen data-id="Beranda" data-en="Home"
data-ph-id / data-ph-en Ganti placeholder input data-ph-id="Cari..." data-ph-en="Search..."
data-aria-id / data-aria-en Ganti aria-label (aksesibilitas) data-aria-id="Tutup menu" data-aria-en="Close menu"
data-lang-show Tampilkan blok konten hanya untuk bahasa tertentu data-lang-show="id" (disembunyikan saat EN)

Contoh Implementasi di HTML

<!-- Teks biasa -->
<h1
  data-id="Jelajah Artikel"
  data-en="Explore Articles">
  Jelajah Artikel
</h1>

<!-- Placeholder form -->
<input type="email"
  data-ph-id="Alamat email Anda"
  data-ph-en="Your email address"
  placeholder="Alamat email Anda" />

<!-- Blok konten penuh (hanya tampil di bahasa ID) -->
<div data-lang-show="id">
  Konten eksklusif Bahasa Indonesia
</div>

<!-- Blok konten penuh (hanya tampil di bahasa EN) -->
<div data-lang-show="en">
  English-only content block
</div>

5. Alur Deteksi Bahasa (lang.js v2.0)

1
FORL Prevention — Sebelum DOMContentLoaded, sembunyikan body jika localStorage sudah punya pilihan. Mencegah "kedipan bahasa".
↓
2
Cek localStorage (key: rm_lang) — Jika ada 'id' atau 'en' → pakai langsung, skip langkah berikut.
↓
3
Deteksi Browser Language — Baca navigator.language. Jika id-* → pakai ID. Sinkron, tanpa network request.
↓
4
IP Geolocation — Fetch ipapi.co/json (timeout 4 detik). Jika country_code === 'ID' → ID, selain itu → EN.
↓
5
applyLang() — Update semua elemen DOM, <html lang>, widget dropdown, dan simpan ke localStorage.
Sinkronisasi lintas halaman: Karena pilihan disimpan di localStorage, pengguna yang memilih EN di halaman artikel akan tetap melihat EN saat membuka halaman produk, keranjang belanja, hingga checkout — tanpa ada reset.

Public API (Debug via Console)

// Dapatkan bahasa aktif saat ini
RMlang.get()          // → 'id' atau 'en'

// Paksa ganti bahasa secara programatik
RMlang.set('en')      // ganti ke English
RMlang.set('id')      // ganti ke Indonesia

// Reset preferensi dan deteksi ulang via IP
RMlang.reset()        // hapus localStorage, fetch IP ulang

6. Anti "Layar Goyang" di Mobile (Horizontal Overflow)

Tiga lapis perlindungan sudah diterapkan di semua template:

Lapisan 1: CSS Global di <style> setiap halaman

/* Wajib ada di semua halaman — ini garis pertahanan pertama */
html, body { overflow-x: hidden; max-width: 100%; }
*, *::before, *::after { box-sizing: border-box; }
img, video, table { max-width: 100%; }

Lapisan 2: Viewport meta tag yang benar

<!-- Wajib ada, terutama `viewport-fit=cover` untuk notch iPhone -->
<meta name="viewport"
      content="width=device-width, initial-scale=1.0, viewport-fit=cover" />

Lapisan 3: OverflowGuard di layout.js

// Aktif otomatis di localhost — nonaktif di production
// Deteksi elemen yang melebihi viewport dan tandai merah
function runOverflowGuard() {
  var isLocal = location.hostname === 'localhost'
             || location.hostname === '127.0.0.1';
  if (!isLocal) return;
  // Highlight elemen offending dengan outline merah
}
Penyebab umum overflow: elemen dengan lebar width: 400px (fixed), tabel tanpa overflow-x: auto, gambar tanpa max-width: 100%, atau text panjang tanpa word-break: break-word.
